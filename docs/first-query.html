From a question to a running SRE notebook

The skill lives with Claude or Codex on your machine. The code runs inside Meta's Secure Research Environment, which has no internet. The bridge between them is a paste. Here is the whole round trip for a first query, shown in R — the skill’s verified layer — and what the skill asks for when you are done. The Python mirror is languages/python/jobs.md, documented and not yet field-tested.

Get R that already knows the API's traps

Every line below follows a rule in the skill. The ones that matter most are called out underneath.

climate_2026q1.R
mcl_fromJSON()IDs are 15 to 19 digits. Parsed as numbers they round above 2^53 or print as 9.6e+14. This keeps them character, always.
limit = 100LIntegers need the L suffix through reticulate, or the API rejects the parameter.
mode = "SNAPSHOT"Freezes the result set so the dataset can be re-read, shared and cited. Name and description are required alongside it.
mcl_wait_for_job()Compares status case-insensitively and times out, so the loop can neither spin forever nor read a half-written result.

when the question is answered

Send back what the session taught

The skill is transcribed from Meta's documentation, and only a live response shows where the documentation is wrong. So whenever a response disagrees with the skill, or confirms something it had only read, Claude says so on the spot. When you are done, if it noted anything, it offers once:

This session taught 1 thing this skill did not know: the API rejected the window with subcode 3790079 because until was today, and the skill only says until must be after since. Want me to write it up as a field report?
Say yes and the report is drafted in the skill's template. Say no and it is dropped; the offer is not repeated.
field report · paste into the issue form
Never any data.A report carries error messages, subcodes, endpoints, parameters, field names and counts. Post text, user names and result rows stay in the SRE.
Where it goes.The Field report form on the skill's repository has one field per heading, so the draft pastes in section by section. With a clone, it becomes a pull request instead.
